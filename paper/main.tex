\title{When Do Errors Compound Across Languages?\\
A Descriptive Study of Multilingual Long-Horizon Tool Use}

\author{Anonymous ARR submission}

\begin{document}

\begin{abstract}
Multilingual tool-use evaluations often measure individual calls, but users
need agents to complete tasks that require several calls. We present an
execution-based protocol for comparing language differences at the step and
task levels. It combines isolated tool-call replay with correct preceding
context, an English-relative independence baseline, and analysis of failures
and outcomes after departure from a reference call sequence. We apply the
protocol to paired BFCL multi-turn tasks across eight languages and two
models, localizing user queries while keeping tool schemas in English.
The contribution is a reproducible way to distinguish isolated call validity,
task-level deviation from a product baseline, and reference-path differences
that may include valid alternatives. Scenario resampling, sensitivity checks,
and synthetic calibration make the assumptions and limits of these
measurements explicit. The study supports descriptive comparisons rather
than causal claims about error propagation. Code is available at \url{https://anonymous.4open.science/r/multilingual-compounding-5A88/}
\end{abstract}

\section{Introduction}
\label{sec:intro}

Language models can complete tasks by calling external tools over several
turns \citep{patil2025bfcl,yao2025taubench}. Multilingual evaluations report
failures when argument values follow the user's language but the tool expects
fixed English values \citep{mlcl2026}. Other work varies the languages of both
queries and tool descriptions \citep{arabicenglish2026}. These studies show
why language matters for tool use, but they do not separate isolated call
validity from task success relative to an independence baseline.

A language difference measured on individual calls does not determine the
difference over a full task. Earlier mistakes can change the context seen by
later calls, while repair or a valid alternative sequence can still lead to
success. Work on multi-turn reliability and controlled error injection
studies these effects \citep{turnwise2026,agentprop2026}. Our question is how
to compare step-level and task-level language differences without treating
every departure from a reference sequence as error propagation.

We study twenty distinct BFCL v3 scenarios in eight languages with two model
configurations and two seeds. User queries are translated while tool schemas
remain in English. Task outcomes come from execution checks. Each reference
call is also replayed with correct preceding context, allowing us to measure
step validity without carrying forward earlier model errors. We then compare
the task-success ratio to English with the ratio predicted by a product of
step validities. This baseline is a comparison model, not an assumption that
real agent calls are independent.

Our contributions are:
\begin{enumerate}
\itemsep0.15em
\item \textbf{A multilingual measurement protocol.} We separate isolated
call validity, task-level deviation from an independence baseline, and
outcomes after divergence from a reference path.
\item \textbf{A reproducible paired evaluation.} We provide translated
queries, execution traces, replay outcomes, and analyses for the selected
BFCL scenarios, together with translation checks and scenario-level
uncertainty estimates.
\item \textbf{Checks on interpretation.} Synthetic calibration and
scenario holdouts test the limits of the metrics. Reference-path alignment
makes explicit that some detected divergences are valid alternatives.
\end{enumerate}

The study is descriptive and limited to the selected tasks and models.
Figure~\ref{fig:teaser} illustrates the motivation; it is not an observed
trajectory.

\section{Related Work}
\label{sec:related}

\paragraph{Multilingual tool use.} \citet{mlcl2026} study language-mismatched
argument values in single-turn calls. \citet{arabicenglish2026} compare Arabic
and English queries and tool descriptions across task types, including
complex and multi-step calls. Their language-component comparison differs
from our fixed English interface and step-to-task baseline. Multilingual
multi-turn evaluation also examines context retention
\citep{m2lingual2025}. We use paired localized tasks to compare isolated
reference-call validity with full-task outcomes.

\paragraph{Multi-turn reliability.} Related work studies tool planning,
agent workflow reliability, and confidence calibration
\citep{denoiseflow2026,phgpo2026,htc2026}.
\citet{turnwise2026} compare multi-turn and single-turn performance, while
\citet{agentprop2026} use controlled error injection to measure propagation.
Conversation studies also document failures over multiple turns
\citep{laban2025lostinconversation}. We do not inject errors or estimate a
causal propagation effect; we measure language differences under a fixed
tool interface.

\paragraph{Execution-based evaluation.} BFCL v3 checks multi-turn task
outcomes against environment state \citep{patil2025bfcl}. Related benchmarks
include $\tau$-bench, $\tau^2$-bench, ToolBench, and StableToolBench
\citep{yao2025taubench,barres2025tau2,qin2024toolbench,guo2024stabletoolbench}.
Our experiments use the pinned BFCL evaluator rather than a model judge.
Translate-test, which routes input through English
\citep{shi2022language}, remains a possible future comparison.

\section{Setup and Measures}
\label{sec:setup}

At each step, an agent emits a tool call, receives the environment's response,
and chooses its next action. A call specifies a function and its argument
values. BFCL checks task success against the resulting
system state \citep{patil2025bfcl}. It can accept a successful path that differs
from the reference call sequence. We use the pinned execution checker rather
than a model or human judge.

We evaluate English, Arabic, Turkish, Chinese, Hindi, Japanese, Spanish, and
Swahili. Only user-facing queries are localized. Tool schemas specify the
available functions and their accepted arguments, and remain in English.
Translation must preserve both meaning and exact task arguments.
This setting measures language differences at a fixed interface and does not
cover translated tool schemas.

\paragraph{Task selection.} We select twenty distinct scenarios, with one
category variant per scenario and five tasks in each of four multi-turn
categories. Selection precedes model outcomes: complete scenario families
with $8$--$10$ reference calls are sorted by descending horizon and numeric
ID, then assigned to categories in round-robin order. Category and scenario
are not independently varied, so we do not estimate category effects.
The selected tasks have seven ten-call, twelve nine-call, and one eight-call
reference sequences, for a mean length of $9.3$.

The eight languages give $160$ task--language queries. With two models and
two seeds, the data contain $640$ full trajectories and $5952$ isolated
replays. Each model--language cell has $40$ trajectories and $372$ replays.
A \emph{critical step} is an executable call in the reference sequence;
non-execution turns are excluded from the reference length and replay count.
We denote the model by $b$ and the query language by $\ell$.

\paragraph{Task success and isolated validity.} $T(\ell,b)$ is the success
rate over the selected task--seed trials. $p(\ell,b)$ is the validity rate
of reference calls replayed with correct preceding context. The latter uses
the pinned BFCL multi-turn checker. Replaying each call separately prevents
earlier model errors from entering its context. Validity measured inside
a full trajectory would already include those earlier effects.

Let $y_i$ be the binary outcome of full task trial $i$, and $v_j$ the binary
validity outcome of isolated replay $j$. For $N$ task trials and $M$ replay
trials in a cell, we report add-one-smoothed rates:
\begin{equation}
\begin{aligned}
\hat T(\ell,b)&=\frac{1+\sum_{i=1}^{N}y_i}{N+2},\\
\hat p(\ell,b)&=\frac{1+\sum_{j=1}^{M}v_j}{M+2}.
\end{aligned}
\label{eq:rates}
\end{equation}
Smoothing keeps the log ratios finite when observed counts are zero.
We write these estimates as $T$ and $p$ in the remaining equations. Rates
pool trials rather than average seed-wise rates.

\section{Comparing Step and Task Differences}
\label{sec:compound}

\subsection{An independence baseline}
We ask whether the task-success difference from English exceeds the
difference predicted by isolated call validity. Define a comparison model
in which a task succeeds \emph{if and only if} all $K$ critical calls are
valid. If their validity events are mutually independent with the same
probability $p(\ell,b)$, their product gives the baseline
$T_{\mathrm{ind}}(\ell,b)=p(\ell,b)^K$. The predicted task-success ratio to English is therefore
\begin{equation}
r_{\mathrm{ind}}(\ell,b)
=\left(\frac{p(\ell,b)}{p(\mathrm{EN},b)}\right)^K.
\label{eq:indep}
\end{equation}
This defines a baseline, not a model of real agent behavior. Actual calls
can differ in difficulty, depend on earlier state, and repair mistakes.
We use $K=9$, the rounded mean reference length, and check $K=8$ and $10$.
A second baseline uses $\prod_{k=1}^K p_k(\ell,b)$, allowing validity to
vary by reference position. Each $p_k$ is add-one smoothed over tasks and
seeds that contain that
position; when a resample has no observation at a position, the code uses
the common $p$. This is not a task-specific difficulty model. Both remain
product baselines.

Let $r_{\mathrm{obs}}=T(\ell,b)/T(\mathrm{EN},b)$. Our main comparison is
\begin{equation}
\Delta(\ell,b)=\log r_{\mathrm{obs}}-\log r_{\mathrm{ind}}.
\label{eq:delta}
\end{equation}
A negative $\Delta$ means that the observed task-success ratio to English
is lower than this baseline predicts; a positive value means it is higher.
Neither sign identifies the cause of the difference.
For comparison with the original analysis, we also report the
\emph{compounding factor}:
\begin{equation}
\mathrm{CF}(\ell,b)=\frac{\log r_{\mathrm{obs}}}{\log r_{\mathrm{ind}}}.
\label{eq:cf}
\end{equation}
CF equals one when the two log ratios agree and the denominator is nonzero.
If $r_{\mathrm{ind}}<1$,
CF above one means a larger language gap than the baseline predicts.
That interpretation reverses when $r_{\mathrm{ind}}>1$.
We report CF only when $|\log r_{\mathrm{ind}}|\geq .05$, since division
by a small step-level gap is unstable. $\Delta$ does not divide by that
gap and remains available when CF is omitted.

Shared multiplicative factors cancel in the ratio only if they are the same
across languages. Language-specific repair or task difficulty need not
cancel. The synthetic checks in Appendix~\ref{app:calibration} illustrate
these assumptions and the limits of the bootstrap-tail statistic.

\subsection{Failure stages and reference-path outcomes}
For each invalid isolated replay, we assign one of three stages using its
execution record and the reference call sequence:
\begin{enumerate}
\itemsep0.1em
\item \emph{Intent/tool selection}: the call is missing or unparseable,
or its function does not appear in the reference sequence.
\item \emph{Argument/parameter}: the function matches but its arguments
fail the reference check, unless BFCL reports a state/context mismatch.
\item \emph{Sequencing/planning}: the function occurs at another position
in the reference sequence, or the checker reports a state/context mismatch.
\end{enumerate}
These are programmatic, reference-based labels rather than human judgments
of the model's intent. They can also label valid alternatives as mismatches.

Full-trajectory outcomes are analyzed separately. We greedily align emitted
calls to the ordered reference. A call that does not match the next unmatched
reference call marks a \emph{detour}. Detour-to-failure is the fraction of
flagged trajectories that end unsuccessfully; post-detour success is the
fraction that end successfully. The two rates sum to one; analysis files call the latter rate recovery.

Extra calls, different orderings, and valid alternative paths can all receive
this flag. Success after a detour therefore does not necessarily mean recovery
from an error. We compare outcomes within shared bins defined by the number
of valid and total isolated replays for a task trial. Bin weights are the
smaller of the English and non-English trial counts. This adjusts for measured
replay validity, but does not remove scenario differences or identify a causal
recovery effect.

\section{Experiments}
\label{sec:experiments}

We use Gemini 3 Flash Preview and Claude Sonnet 4.6 on the selected BFCL v3
multi-turn tasks. Full trajectories and isolated replays use the same task,
query language, model configuration, and seed. Execution uses the pinned
benchmark snapshot. Appendix~\ref{app:protocol} records the selection,
localization, model settings, and analysis commands.

\paragraph{Translation checks.} Direct AI review covered all $140$
non-English query sets before collection and corrected $86$. We then
refreshed backtranslations and checked exact source quotations, query hashes,
and empty-turn alignment. An author subsequently reviewed a mixture of
target-language text and English backtranslations and judged the translations
adequate. This is not independent bilingual validation. LaBSE scores and
artificial-error probes provide an additional consistency check, reported in
Appendix~\ref{app:translation_quality}; they are not accuracy percentages.

\paragraph{Uncertainty and sensitivity.} The primary bootstrap resamples
twenty scenarios with $5000$ draws, keeping both seeds and all languages of
each scenario together. Task--seed resampling is a secondary sensitivity
check. We also vary $K$, compare the two product baselines, and omit one
scenario or language at a time. These checks describe the selected tasks;
they do not establish representative coverage of unseen tasks.

The saved analysis includes directional bootstrap tails and
Holm--Bonferroni adjustment over fourteen non-English comparisons. Synthetic
null checks show that these tails are not calibrated significance tests.
Increasing the resample count resolves the earlier numerical floor but does
not fix calibration. Appendix~\ref{app:calibration} retains the calibration
and conditional power diagnostic; Appendix~\ref{app:task_sensitivity}
reports scenario influence.

\paragraph{Reproducibility.} The evidence package contains localized queries,
execution traces, isolated replay outcomes, metric and stage-labeling code,
and the pinned BFCL checkout. The README gives commands for auditing the
saved collection and regenerating the analyses without new model-API calls.
Historical pilot inputs and results remain separate from the fresh cohort.

\section{Results}
\label{sec:results}
Table~\ref{tab:cf} and Figure~\ref{fig:results} report the fresh twenty-scenario
comparison. English has smoothed step validity $p=.623$, task success $T=.595$
for Gemini, and $p=.591$, $T=.548$ for Claude. Their English product
baselines predict task success $.014$ and $.009$, respectively, well below
the observed rates. The product is therefore a comparison baseline rather
than an absolute model of success. Step and task gaps can differ in sign. Hindi/Gemini has $p=.628$ but $T=.333$: isolated replay predicts a small
advantage over English, while task success is lower. Its $\Delta=-.657$ is
negative under both the common and position-specific nulls (position-specific
$\Delta=-.890$). This discrepancy is a candidate for follow-up, not a causal
propagation result.

Nine of fourteen non-English cells have $r_{\mathrm{ind}}>1$. A CF above one
cannot be interpreted uniformly as a language penalty, and denominators near
zero can produce unstable signed ratios. Hindi/Gemini has CF $-7.538$, with a
scenario-bootstrap interval spanning both signs. We therefore foreground
$\Delta$ and retain CF as a baseline-dependent diagnostic. All seven Claude
cells have negative $\Delta$; Gemini has negative values for Hindi and Swahili
and positive values for the other five languages. No formal between-language
heterogeneity test was run.

\paragraph{Horizon and scenario sensitivity.}
We use $K=9$, the rounded mean horizon, with $K\in\{8,9,10\}$ and both nulls.
Common-null $\Delta$ signs are unchanged over this sweep. The position-specific
null changes Turkish/Gemini and Chinese/Gemini from positive to negative at
$K=8$, so baseline and horizon choice can change the directional reading.
Individual scenarios also matter. At $K=9$, omitting one scenario changes
the common-null $\Delta$ sign in four of fourteen cells and CF reportability in
five. The position-specific null also has four sign-sensitive cells.
Appendix~\ref{app:task_sensitivity} reports the full influence analysis.
The scenario intervals are broad; synthetic calibration prevents treating
their directional tails, even after Holm adjustment, as confirmatory tests.

\paragraph{Reference-relative outcomes.}
Greedy alignment marks $624/640$ trajectories as detours, including all
$314/314$ successful traces and all $46/46$ successful English traces. Thus it
captures valid alternatives as well as errors. Sequencing/planning labels
dominate invalid replay steps: $.699$ of English and $.675$ of non-English
failures (Table~\ref{tab:stage}). The argument/parameter shares are $.116$ and
$.131$, respectively. This slice does not expose an argument-boundary-dominated
mechanism that would justify claiming a canonicalization benefit.

\paragraph{Scope checks.} The earlier pilot used four category variants of
one scenario and contained translated exact search literals in $12/28$
non-English rows. Its inputs and outputs are preserved separately and are
not pooled with the fresh cohort. The two current models were selected after
English-baseline diagnostics; GPT-4o was not recollected
(Appendix~\ref{app:protocol}). Conclusions are limited to these model
configurations and the selected BFCL tasks.

\section{Discussion}
\label{sec:discussion}
An isolated-step advantage over English can coexist with lower full-task
success. The protocol measures that discrepancy without attributing it to a
causal propagation mechanism. $\Delta$ is easier to compare than CF when
the step-level language gap is small or reverses direction.

Sequencing labels are common in both language groups, and reference detours
include all successful traces. These measurements do not establish a repair
benefit. Controlled planning and recovery experiments would be needed to
separate actual errors from valid alternative paths. Schema-based argument
correction, translate-test, and self-repair remain possible follow-up designs.
The current evidence does not justify presenting any of them as an evaluated
mitigation.

\section{Conclusion}
\label{sec:conclusion}
We present a reproducible protocol for comparing isolated call validity,
task success relative to a product baseline, and outcomes after divergence
from a reference path. Its application to multilingual BFCL tasks shows
why these measurements should be reported separately. The selected tasks
support descriptive comparisons, not causal conclusions about propagation
or recovery. Future evaluation should broaden scenario coverage and test
mechanisms through controlled interventions.

\section*{Limitations}
The study covers two model configurations and twenty selected BFCL scenarios.
Selection is independent of model outcomes but restricted to complete
scenario families with $8$--$10$ reference calls. Category and scenario are
not independently varied. Other environments, longer tasks, translated tool
schemas, and broader decoding variation are outside scope. Two seeds do
not establish decoding stability.

The independence baseline uses an effective length and pooled validity rates.
Neither it nor the position-specific product models actual dependencies or
repair. Scenario resampling retains paired observations but does not make
the selected tasks representative. Synthetic calibration is conditional on
its stated generator and does not validate the bootstrap tails as p-values.
No formal between-language heterogeneity test was performed. CF is unstable
near a negligible step gap and changes interpretation when that gap reverses.

Reference alignment flags valid alternatives, including every successful
trace in this study. Weighted replay-count bins do not identify causal
recovery. Translation received AI review, exact-literal/alignment checks,
and subsequent author review using target text and backtranslations.
Independent bilingual validation was not performed. LaBSE cannot establish
semantic accuracy or fluency. The historical one-scenario pilot has disclosed
translation confounds and remains separate. No mitigation was evaluated.

\section*{Ethics Statement}
We use public benchmark tasks and model outputs, with no human-participant
study or private user records. Model APIs were used under their terms.
Language-dependent tool failures can disadvantage users, but this study does
not establish population-level effects. AI assistance was used for translation
review, code, and writing; execution outcomes use the pinned BFCL checker.
The authors are responsible for the manuscript and the accuracy of its
reported evidence.

\section{Controlled CF Calibration and Power Diagnostic}
\label{app:calibration}

We check the ratio construction under explicit synthetic processes using the
released \texttt{compute\_cf} and \texttt{bootstrap\_cf} functions. The script
\path{scripts/run_cf_calibration.py} writes the complete parameters, seeds,
and outputs to \path{analysis/bfcl/cf_calibration_summary.json}.
These checks illustrate specified processes; they do not validate a general
model of agent recovery or replace the BFCL experiment.

\paragraph{Analytic process checks.} Set $K=10$, $p_{\mathrm{EN}}=0.90$,
and $p_{\mathrm{TR}}=0.86$. With independent step outcomes and multiplicative
survival $\alpha_\ell$, task success is $T_\ell=\alpha_\ell p_\ell^K$. Hence
\[
\mathrm{CF}=1+
\frac{\log(\alpha_{\mathrm{TR}}/\alpha_{\mathrm{EN}})}
{K\log(p_{\mathrm{TR}}/p_{\mathrm{EN}})}.
\]
A shared survival factor cancels. In contrast, additive rescue obeys
$T_\ell=p_\ell^K+\rho_\ell(1-p_\ell^K)$; even equal $\rho$ need not cancel.
Table~\ref{tab:synthetic_cf} reports population expectations, with corresponding
stochastic checks in the released JSON. It records the per-process sample
counts, seed structure, and base seed $20261010$.

Unequal-position difficulty uses eight English positions at $.96$ and two at

remain $.90$ and $.86$, but only the position-specific product gives population

$q(.86/.90)$; calls are independent conditional on $q$.
Conditional step independence can therefore produce $T>p^K$ in both languages
while preserving $\mathrm{CF}=1$ under this specified shared factor. This
cancellation is conditional on the generating process. In the extra-loss
simulation, $5000$ bootstrap draws give a CF interval $[2.287,2.632]$ and a
$\Delta$ interval $[-.743,-.610]$.

$(T_{\mathrm{EN}},T_{\mathrm{TR}})=(.900,.300)$ from the original one-scenario
pilot. This is an illustrative historical plug-in alternative, not a power
estimate fitted to the fresh twenty-scenario results.
We use $200$ Monte Carlo datasets and $5000$ scenario-cluster resamples per
dataset. Wilson intervals measure Monte Carlo uncertainty.

The family false-positive rates exceed the nominal $.05$ in several settings.
Thus the one-sided bootstrap-tail statistic is not calibrated as an inferential
p-value under this dependence structure. At twenty scenarios, target null
rejection is $2/200$ ($.010$, interval $[.003,.036]$), family rejection is
$14/200$, and adjusted target power for the historical plug-in alternative is
$10/200$. These are conditional
simulation results, not evidence that a twenty-scenario collection is adequately
powered. Empirical tail statistics remain descriptive diagnostics.

\paragraph{Numerical resolution.} The statistic is
$p_{\mathrm{tail}}=(1+\#\{\Delta^*\geq0\})/(1+n_{\mathrm{boot}})$.
The smallest first Holm-adjusted value is $14/(n_{\mathrm{boot}}+1)$:
$.06965$ at $200$ draws, $.05$ at $279$, and $.00280$ at $5000$.
More draws remove this numerical floor but neither add independent scenarios
nor correct null miscalibration. CF is reportable only when
$|\log r_{\mathrm{ind}}|\geq.05$; $\Delta$ remains available when CF is unstable.
The earlier $80$-replicate calibration is retained as historical output rather
than treated as a replication of these expanded checks.

\section{Per-Experiment Protocol}
\label{app:protocol}
Task and step outcomes are execution-scored. Query review checks input
fidelity; it does not judge model outcomes.

\paragraph{Localization.} The expanded collection uses 20 BFCL v3 multi-turn
tasks and 160 localization records: 20 English source records and 140
non-English records across seven languages. Direct-text AI review compared
each localized row with its English source and backtranslation. It corrected
86 rows and marked 54 as reviewed without edits. Individual human approval
was pending at collection. An author later reported reviewing the translation
set through a mixture of target text and English backtranslations and judged
it adequate. This attestation is recorded separately from the frozen cache;
it does not represent independent bilingual expert validation.
The review records preserve source and localized
content hashes, exact quoted literals, and turn alignment, including empty
turns. Tool schemas and reference solutions remain in English. The historical pilot
had quoted-literal drift despite its automatic checks. AI review and
corrections in the fresh cohort do not count as human validation.

\paragraph{BFCL runs.} The fresh cohort runs 20 selected tasks, each with a
distinct underlying scenario ID, in eight languages with two models and two
seeds. Using the official executable evaluator yields 640 full multi-turn
trajectories. We separately measure single-turn validity $p(\ell,b)$ by
replaying each critical step in isolation with gold preceding context
(Section~\ref{sec:setup}); do not read $p$ from the in-trajectory marginal,
which would make the compounding comparison circular. The 186 gold calls
produce 5952 isolated replay records across languages, models, and seeds.
The environment preflight reconstructed and self-replayed all 186 gold calls.
We also record step and token counts. Output: trace database;
Table~\ref{tab:cf} columns $p,T$.

\paragraph{Reproducibility note.} For the expanded BFCL comparison, the two
models use temperature $0.001$ and seeds $0$ and $1$, recorded under run
labels \texttt{expansion\_seed0} and \texttt{expansion\_seed1}. Prompting
follows the official BFCL executable evaluator and task formatting; where
provider APIs expose an explicit seed, the released pipeline passes through
the seed encoded in the run label.

\paragraph{BFCL compounding analysis.} Estimate effective horizon $K$ from the
reference BFCL trajectories. The expanded cohort has mean $K=9.30$, rounded to
$K=9$ for the primary table; sensitivity checks use $K\in\{8,9,10\}$. Compute
$T_{\mathrm{ind}}$ and the compounding factor (Eqs.~\ref{eq:indep}--\ref{eq:cf})
under common and position-specific nulls. The primary uncertainty
analysis resamples underlying scenario IDs with 5000 bootstrap resamples and
seed $0$; task--seed resampling is a conditional sensitivity analysis.
Bootstrap tails, including Holm-adjusted tails, are uncalibrated directional
diagnostics and are not inferential $p$-values. Output: Table~\ref{tab:cf}
column $\mathrm{CF}$. The estimates do not establish a mechanism.

\paragraph{Decomposition and follow-up scope.} Stage shares in
Table~\ref{tab:stage} classify invalid isolated replay steps. Full-trajectory
alignment separately supplies detour flags and eventual outcomes. Shared
bins of valid and total replay counts have weights equal to the smaller
English/non-English trial count, not individual trajectory matches.
Canonicalization, translate-test, and self-repair were not evaluated. A
future controlled comparison should report task success, added calls, latency,
and tokens before attributing an improvement to argument correction.

\paragraph{Robustness checks.} The legacy automatic filter requires fidelity at
least 3 and reference-call invariance; it retains 9 of 160 task--language
records, corresponding to 36 full runs and 360 replays. Its anchors include
gold-derived strings absent from the English source, so we retain it only as a
failed legacy-filter diagnostic, not as evidence of full-cohort robustness.
The completed reviewed-policy rerun validates source and target hashes, exact
source quotations, aligned turns, and resolved AI review records. It retains
all 160 localization records and the same 20 scenarios across languages,
models, and seeds: 640 full runs and 5,952 replays. The subsequent author review
does not change this gate or establish independent semantic validation.
Other completed sensitivity analyses cover $K\in\{8,9,10\}$,
leave-one-language-out comparisons, and two-seed variability. A
second-environment holdout was not run, so the robustness evidence is limited
to BFCL.

\paragraph{GPT-4o diagnostic exclusion.} Earlier diagnostics with
\texttt{gpt-4o-2024-08-06} produced $0/8$ English task successes and $58/80$
valid replays through OpenRouter, and $0/4$ successes with $27/40$ valid
replays through direct OpenAI serving. We did not recollect that configuration
for the twenty-scenario study. These small diagnostic runs are retained
separately and do not establish general model performance. The current
comparison is limited to the two selected configurations.
